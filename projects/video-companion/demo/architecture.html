一只小电视背后的 8 个系统 与 9 张 DAG

面试官问"你打算怎么把它做出来"——答案不是"写一个 Agent"。它是一条离线生产链、一条在线决策链，加一层反馈闭环、一套记忆与性格模块和一套后台配套。本页把它们画成同一套 DAG，点任意节点可看职责、输入输出、成本与答辩话术。

离线 · DAG Workflow

视频上传时一次性跑完：抽帧 / ASR / OCR → 分段 → 多路解读 → 仲裁 → 剧本资产。
Airflow / Temporal / 自研调度——可重试、可回放、可版本化。

在线 · 有限状态机 FSM

观看时每一刻做什么：陪看 / 困倦 / 睡眠 / 外出，事件驱动、有回流。
XState / useReducer——这不是 DAG，是状态机，二者别混。

表达 · React 渲染层

出门 / 睡觉 / 回复 / 抒发感想 × 开心 / 困倦 / 无聊——行为乘情绪是组合爆炸，用状态驱动的组件树解，不用 if-else 堆 DOM。
React + SVG + CSS 动画——铁律：组件里不写业务决策。

为什么不是"一个 workflow 全搞定"？ workflow 擅长无环、可批处理的离线生产；在线观看是事件驱动、带状态回流的过程，用 DAG 描述会丢掉"状态"这个核心。React 是渲染层，不是编排层。三层各司其职，才是这个产品能控成本、能评估、能迭代的原因。

读图规则：每张图实线按流程顺序连；节点颜色 = 它属于哪一层；彩色虚线回弯 = 该系统内部自循环（没有这个小循环，系统就不会随使用变好）。

STATE

状态里到底装什么：8 个分区

WHY

为什么拆成 5 个节点 / 哪些是大模型节点

节点是不是大模型为什么单独成节点
START 触发否 · 事件外部事件进图的入口，不是处理步骤
① 看现状 observe否 · 纯规则 + 状态判定读 State、归一化事件、判定模式转移（睡 / 出门 / 留下来）。拆出来，下游拿到的是已判定的事实，不用各自猜状态
② 反应闸门 gate否 · 纯规则最关键的一拆：只决定"说不说 / 出哪几路 / 多强"，不管模式转移。把"要不要花钱"变成生成之前就能强制执行的判断。"极少主动插话"靠它，不靠模型自觉
③ 取资料 retrieve否 · 查表 / 向量检索剧本已在上传时预处理好，这里只按时间点切片。拆出来，生成环节不用重复理解视频
④ 组织语言 generate是 · 唯一的热路径大模型调用把唯一烧钱的一步单独围起来：可跳过、可换模型、可单独评估、可限流
⑤ 画出来 render否 · 前端组件状态 → UI 的纯映射。拆出来，换模型不动渲染，改表情不动决策
回答"为什么不能直接让阀门决定动作"：可以，但要把阀门拆成两半。模式转移（睡 / 出门）是状态判定的结果，放 observe 更对——它是"事实"，不是"许可"；反应通道（说不说）才是闸门，必须在生成前强制执行，不靠模型自觉。合起来做也行，代价是 badcase 归因糊成一团、状态转移规则被成本逻辑裹住。拆开后三件事都能单测：判定错看 observe，插话错看 gate，剧透错看切片。5 个节点仍是最小集——只是职责边界挪了一刀。
大模型节点全景（别只盯着在线）： 热路径只有 generate 一个，且必须由用户主动触发；离线侧还有大模型——视频理解里的多路解读与事实仲裁（上传时一次性，可用重模型）、概要记忆的摘要更新（低频）、Eval 的 LLM-as-judge（离线批处理）。这正好对上三层成本模型：一次性预解析 / 查表反应 / 按需对话。
面试一句话：离线把理解成本一次付清，在线只做查表与轻量决策，反馈层把每一次互动变成下一次的变量——三层成本模型就是这张图的骨架。
已拍板：注册就有，常驻，全局可关。 用户不做任何启用动作，某天它自己活过来——产品时刻是"你见过它一万次，这是它第一次看回你"。前提是系统级总开关随时可关。由此推出出厂无预设人设：性格从零长起，锁死的只有硬规则（语言、明示 AI、伦理边界、无分发权限）。
DAG 01

输入 → 反应闸门 → 演出帧（本轮定稿）

技术实现的最小骨架。不做意图识别，不做路由——用户不完成任务，输出也不需要分发给不同模块。真正要判断的是"现在该不该有反应、反应多强"，这是规则，不是语义分类。

输入规则闸门（零成本）演出帧渲染彩色虚线 = 内部小循环
为什么不要意图识别：① 没有任务可路由，传统意图识别服务于"订票/退票"这类任务分发；② 输出不是互斥三选一，而是一个可组合的帧；③ 多一层分类就多一个会错的组件，badcase 归因反而更难。唯一例外：少数指令型输入（"我想安静看会儿""你出去玩吧""你还记得什么"）用关键词/正则白名单覆盖即可，撑不起一个分类器。等它开始找片、跨视频检索、带它实现愿望时才需要真正的意图层。
输出 = 一个演出帧，四路通道各自可空，可同时触发。 神态几乎总是非空（在场感来源）；动作与卡片常为空；语言通道默认关闭，闸门放行才生成。一帧可以是「眼神一亮 + 天线立起 + 气泡『火锅！』」——三者互为加强。闸门因此不只判"说不说"，而是判这次输出哪几路、各自强度多少，仍然是规则、仍然零成本。
DAG 02

推理上下文装配：不是全塞，是按预算拼装

推理节点要的东西确实多：剧本、概要、碎片、画像、自己的设定、多轮会话。但剧本大不等于在线要大窗口——整本塞进去只会更贵、更容易跑题、还可能剧透。大窗口留给离线剧本生成；在线只做切片与装配。

不可裁记忆 / 设定会话与输入生成虚线 = 多轮回写
装配优先级（从上到下，裁切时从尾往前丢）：① 硬规则与输出格式（永不裁）→ ② 当前剧情切片 + 防剧透闸门（永不裁）→ ③ 用户这句话 → ④ 当前会话（近几轮原文 + 滚动摘要）→ ⑤ 概要记忆 → ⑥ 碎片记忆（最多一两条，语境相关才取）。用户画像不进 prompt 文本——它只作为行为与语气参数存在，否则就会不小心被念出来，违反"画像不出口"。
多轮对话单独一层，不和长期记忆混。 会话记忆管"刚才说到哪、哪句还没接、这轮情绪是什么"，随会话结束可弃；长期记忆管"我们之间的关系"。做法：保留最近几轮原文 + 一段滚动摘要，老轮次先折叠成摘要再丢弃。否则聊十轮之后，prompt 里全是废话，关键剧情反而被挤出去。

Token 预算为设计口径（非实测）：硬规则约 300 ｜ 剧情切片 800–1500 ｜ 会话 500 ｜ 概要 300 ｜ 碎片 200 ｜ 用户输入 200，合计约 2.5k–3.5k，输出电报体极短。降级顺序：先丢碎片 → 再丢概要 → 折叠会话旧轮 → 去掉邻帧；硬规则与当前剧情段永不裁。

DAG 03

视频理解系统：上传时的一次性生产链

整条链在上传后异步执行，失败可重试、结果可回放。产出不是"摘要文本"，而是带时间索引的结构化剧本资产，全平台所有用户共用一份。

离线节点产物 / 资产质量闸门
关键设计：多路解读分两层合并——事实层（时间线/角色/事件）必须仲裁成唯一版本，观点层（情绪/伏笔/梗点）允许多角度并存。事实层不仲裁，BOT 会自相矛盾；观点层不并存，它就失去"自己的看法"。

两处口径冲突，一并拍板： ① 3.4 起名 vs "参数不可调" → 允许写 alias（称呼/自称），但性格向量仍只由相处渐变，不因一句"你要活泼"跳变；② 5.5 话多/话少 vs "参数不可调" → 不做设置滑杆，改用自然语言临时调闸门阈值，且阈值随时间衰减回基线。
优化总方向：保留 5 个做事节点，补 1 个写回节点 + 1 套完整事件分类 + 3 层 State；把关系参数接到条件边；把行为决策交给模型，规则退到硬约束与成本闸门。下面三章就是这套优化后的详细设计。

MODEL

BOT 行为逻辑：模型驱动，不是规则引擎

行为选择交给小模型（结构化输出），规则退到"硬约束 + 成本闸门 + 帧自洽校验"。常态表情不逐帧调模型——离线情绪曲线在线查表；被事件唤醒才走模型链路；要说话才调大模型。

DAG 04

在线观看链：默认神态，轻点才对话

用户点开视频后，剧本切片随播放时间点加载；默认全程只走神态层（近零边际）。只有用户轻点化身、视频降音量后，才进入 ASR + 上下文合成 + 重型生成。

在线节点上下文注入重型调用（按需）
成本闸门：粉色三节点是唯一的烧钱路径，且必须由用户主动触发。这是把 AI 成本压到可归属增量收入以下的关键——不是模型更便宜，而是绝大多数时间不调用生成模型，调用次数被产品形态锁死。Character.AI 的公开账本说明全栈成本风险，但不能把它的绝对值直接套到平台内产品。
DAG 05

演出系统：一次"反应"是怎么被拼出来的

演出系统是总导演。它接收四类事件，按"神态层 > 对话层"的优先级分发指令。同一件事，能用眼睛说的就不用嘴说。

输入事件演出决策输出通道
为什么单独设一层：没有演出系统，"表情 / 气泡 / 动作 / 卡片"会散落在四个系统里各写各的，很快就不一致。有了它，表情系统只管"怎么画"，行为系统只管"做什么"，演出系统管"先说哪句、用哪种方式"——职责边界干净，也不容易跑偏人设。
渲染层为什么用 React：行为 × 情绪 = 组合爆炸。 出门、睡觉、回复、抒发感想、表演心情，再乘上开心/困倦/无聊/害怕——如果用手工 DOM 操作，每加一个状态都要改一堆分支。声明式组件树让"状态 → UI"变成纯映射：
<Bot state={fsm} mood={emotion}>
  ├─ <Face mood />        眼睛 + 嘴 + 天线（SVG，纯函数）
  ├─ <Bubble text />       语言通道为空则不渲染
  ├─ <Motion action />     探头 / 缩回 / 走开
  └─ <Card item />         安利卡片，可忽略
三种容器复用同一棵树：<Island /> 灵动岛 · <PlayerBadge /> 播放框 · <FullTv /> 整机

关键纪律：决策全部在 FSM 与规则层，组件只接收 props。一旦把"该不该出门"写进 useEffect，这套东西就再也测不动了。

STATE

状态系统：这是状态机，不是 DAG

三大基础状态（陪你看 / 外出 / 睡眠）之间是可以来回流动的——有环，所以画成状态转移图。触发条件来自时间桶、内容兴趣、用户行为与它自己的精力。

稳定状态过渡 / 半可见标注 = 触发条件
反依赖设计落在这里：到点自己睡、无聊自己走开——状态转移由"它的作息"驱动，不由"让你多待"驱动。这也是它对"AI 让人上瘾"质疑的结构性回答：一个会自己离场的伙伴，成瘾机制从根上就不完整。
DAG 06

记忆与性格：一个独立模块，两件事

记忆与性格不属于观看主流程，是独立在旁边的模块：主流程只在"触发"时写入、在"行为"时读取。模块内部仍分两层——记忆记"发生了什么"，性格记"我因此变成了什么样"。

互动信号记忆与性格硬规则（锁死）彩色虚线 = 相处闭环
三个必须能回答的问题：① 存什么——画像（不出口，只塑造行为）/ 概要（关系连续性，可覆盖）/ 碎片（情绪峰值，带性格滤镜）；② 什么时候写——只在峰值写入，所以一亿用户长出一亿只；③ 怎么忘——用户说忘即从概要与碎片移除，未成年人不建长期画像。
同一模块，但不混存储：性格不并入记忆。 记忆可被用户删除、语境相关才提起；性格不可被引用、只影响行为、渐变不可重置。若合并存储，用户说"忘掉这件事"时系统无法判断该删记忆还是该重置性格——删除语义就毁了。关系是单向依赖：记忆 → 性格，性格读记忆的统计特征但不回写。
DAG 07

Eval 系统：badcase 从哪来，又回到哪去

Eval 不是"上线后补个打分"。它从线上埋点与人工抽检采 badcase，按四维评分，归因到具体环节，进回归集，修复后再灰度验证——闭环必须落在图里，否则不可迭代。

采集评分与归因修复与验证
四维评分卡：接住率（用户是否回应）、语言可信度（是不是被读成"故障的 AI"）、剧透率（是否越过了当前时间点）、打扰率（关闭率 / 投诉 / 熬夜）。前三维评"像不像它"，第四维评"该不该在"——护栏指标一票否决，和 AB 实验里的护栏是同一套。
DAG 08

后台配套：没有这些，前面 7 个系统跑不起来

按照"一个 AI 产品经理要能画出组织与工具边界"的标准，列出 8 个配套台。它们不直接产生用户体验，但决定产品能不能上线、能不能改、能不能被审计。

后台能力箭头 = 服务哪个环节
这 8 个台不是八套孤立系统，而是一条闭环：资产版本 → Release → 灰度 → Trace → Eval → 修复版本。本页是"为什么这样设计"的唯一权威状态模型与在线时序（drowsy/error 是覆盖态不是第 4/5 种关系模式；gate 只管说不说、observe 判定模式转移、所有写回统一走 commit）；具体对象与可操作状态在运营工作台，二者共用一份 mock store，口径一致。
内容生产 ↗ Release 与发布 ↗ 灰度实验 ↗ Eval 与修复闭环 ↗ 隐私删除 ↗ 成本账本 ↗

TELL

30 秒怎么讲这套架构

  1. 先给痛点：想分享没人接住；产品是一只明示 AI、常驻播放器角落的小电视。
  2. 再给核心判断：陪伴≠对话，所以神态优先——这是它和所有 AI 陪伴 App 的分叉点。
  3. 展开到系统：离线一条 DAG 做剧本，在线一条状态机做反应，中间夹一层演出系统统一调度。
  4. 点出记忆：记忆独立成系统——三层分工、峰值写入、画像不出口、可问可忘，一亿用户养出一亿只。
  5. 给成本答案：最贵的理解只在上传时做一次；在线只有用户主动开口才烧钱——把变量成本压到可归属增量收入以内。
  6. 给迭代答案：Eval 把 badcase 回流到规则与剧本；后台 8 个台保证能上线、能审计、能灰度。
  7. 收尾边界：总开关可关、参数不可调、关系可沟通；陪伴本体免费，付费买纪念与表达。
